1. A primeira fase de um compilador

O computador não enxerga um programa como nós. Para ele, o código é uma longa fila de caracteres. A análise léxica é a primeira fase do compilador: o scanner lê essa fila e a agrupa em pedaços com significado.

  • Lexema: o pedaço de texto encontrado no código, como numero ou ==.
  • Token: o lexema já classificado em uma categoria, como identificador ou operador relacional.
Exemplo: int numero = 10;

2. Como o scanner decide

  • Lê da esquerda para a direita, um caractere por vez, guardando em que estado está.
  • Maior casamento: continua enquanto o lexema puder crescer. Por isso <= é um token só, e não < seguido de =.
  • Espaços, quebras de linha e comentários são descartados.
  • Se um caractere não se encaixa em nada, registra um erro léxico com linha e coluna e continua, para mostrar todos os problemas de uma vez.
  • O scanner não confere se o programa faz sentido (isso é a análise sintática, da próxima etapa).

3. Os autômatos

Cada tipo de lexema é reconhecido por um autômato finito. Círculo duplo é um estado em que o lexema pode terminar.

4. Como usar esta tela

  1. Escolha um exemplo (o 8 tem erros léxicos de propósito) ou escreva seu código.
  2. Clique em Analisar código.
  3. Veja o resumo, o passo a passo do scanner (com os estados do autômato), o código colorido e a tabela de tokens.
  4. Se não houver erros, veja também a árvore sintática (AST): clique em um nó para destacar o trecho do código e ver a regra da gramática, e use Próximo na construção para ver a ordem em que o parser monta a árvore.
  5. Se houver erros, leia as mensagens (léxicas ou sintáticas): elas dizem a linha, a coluna, o que era esperado e como corrigir.

5. Categorias de token desta ferramenta

Comentários (// linha e /* bloco */) e espaços são ignorados, e não geram tokens.

6. Análise sintática e a árvore (AST)

Depois do scanner, o parser recebe os tokens e confere se eles formam “frases” válidas segundo uma gramática. Se formarem, ele monta uma árvore sintática abstrata (AST), que mostra a estrutura do programa.

Em int resultado = 10 + 5 * 2; a multiplicação aparece abaixo da adição na árvore: é a precedência dos operadores. Em 20 - 5 - 3, a subtração é feita da esquerda para a direita (associatividade).

  • Árvore de derivação: mostra todas as regras aplicadas. AST: guarda só o que importa (sem ;, parênteses ou regras intermediárias). Esta ferramenta exibe a AST.
  • Se o scanner achar erro léxico, o parser não roda: com tokens inválidos, os erros sintáticos seriam enganosos.
  • Os erros sintáticos dizem o que era esperado e citam a regra da gramática violada.

7. A gramática (EBNF)

Estas são as regras que o parser conhece. { x } repete, [ x ] é opcional, | é alternativa.
